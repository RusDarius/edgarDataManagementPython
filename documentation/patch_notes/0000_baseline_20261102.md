## 1. What the platform is

A personal active-management research platform. TradingView screener scans are scored and stored every scan day;
deterministic tools turn the stores into a compiled **briefing pack** and a set of **suites** (one question each,
one folder each); an operator, with or without an agent, turns those into decisions on a real Book: hold, add, trim,
exit, new position, short. The code does the data work. Judgment (which course, which grade, how much) is written by
a person or an agent into one file per day and rendered onto pages.

Two older layers sit underneath and are still runnable: SEC EDGAR fundamentals in MySQL (where the repo's name comes
from) and a set of research engines (edge research, backtests, financial projection).

## 3. Layers

```text
TradingView screener API                         SEC EDGAR / Arelle
        |                                               |
        v                                               v
 producers (scan day)                             MySQL fundamentals
   prediction   all-fields   holdings   edge   MTP   panel store
        |            |           |        |     |        |
        +------------+-----------+--------+-----+        |
                             v                           |
                    compile: briefing pack  <------------+   (print pointers)
                             |
                             v
             suites (27 at the baseline, one folder each in the pack)
                             |
                 +-----------+-----------+
                 v                       v
          data-only pages         judgment.json (person or agent)
                 |                       |
                 +-----------+-----------+
                             v
                 operator pages (HTML) + priors for the next day
```

| Layer | Code | What it must not do |
|---|---|---|
| Clients and scans | `src/data_loaders/`, `src/data_analysis_scripts/` | Decide anything about the Book |
| Stores | `src/db/`, `generic_utils/panel_store.py` | Hold judgment |
| Deterministic tools | `src/generic_utils/` (formulas, fetch, aggregate, top-N with no cutoffs), recipes in `config/generic_utils/*.json` | Carry thresholds, courses, grades or a 0-100 composite |
| Domain rules | `src/operator_briefing/` (eligibility, stance, continuity, sleeves) | Re-derive data the generic layer already has |
| Research engines | `src/edge_research_tools/`, `src/backtests/`, `src/backtracking/`, `src/financial_projection/`, `src/focus_pool_screening/` | Publish a buy list |
| Pages | `generic_utils/canvas_page.py`, templates in `config/generic_utils/pages/`, one Ledger (`canvas_ledger.json`) | Retype data rows; a table points at a suite's CSV or DuckDB |
| Agent | `.claude/skills/`, prompts in `src/research_prompt/` | Write SQL or scripts the CLIs already cover |

## 6. Agent flows

| Flow | Trigger | What the agent does | Output |
|---|---|---|---|
| Daily (full) | `python src/run_operator_day.py --agent` when the day has no judgment file, or the DAILY paste | Reads `briefing_pack.md` once, each suite's `highlights.log`, the regime playbook; rules on every Book line, the Build-50, earnings lanes, shorts and tape names inside one budget (0-2 NEW, 0-2 ADD, 0-2 TRIM / EXIT, 0-2 event, 0-1 short); writes `judgment.json` from the skeleton; previews cash with `capital-plan`; renders with `page-all --strict`; writes priors | Pages in the run folder, `judgment.json`, priors |
| Daily update | The same command when a judgment exists, or `run_daily_refresh.py --update-day D` and the UPDATE paste | Reads only `update.md` (names whose fields moved past thresholds, kills crossed, after-hours moves, letter changes), edits only those names, re-renders | The same pages, same judgment, a new run folder |
| One-suite pastes | Blocks in `src/research_prompt/agent_copy_paste.txt` (MOVERS, RISK, FORWARD, PLAYBOOK, WISDOM, HORIZON, BACKTRACK, CAPTURE, GMV, EARNINGS WEEK, WEEK PLAYS, CATALYST OUTLOOK, PRINT NIGHT, DETERIORATION, PATHWAY, SIGNAL LAB, ALPHA MODEL, POST-EARN, DEEP DIVE on themes, ...) | The skill named in the block: run or reuse the suite, read its highlights, write the page or stop at the folder (`duckdb output`) | A suite folder, optionally a page |
| GMV with a page | `python src/run_gmv_lens.py --agent` | The GMV prompt on that suite | `gmv-YYYYMMDD` |
| Named-ticker questions | Free text | `scan-evidence` (lookup, stance, compare) before any new SQL | Lines in chat |

The contract between the two halves: the agent never recomputes what a suite wrote, records any extra deterministic
scan in the judgment's `scans` list so UPDATE can replay it, and every page table points at a file.

## 8. Rules a reviewer needs (full text in `CLAUDE.md`)

1. No invented 0-100 composite. `rr`, `bo`, `band_payoff`, IC, the alpha forecast are separate columns and orders.
2. Generic code has no thresholds. Eligibility, courses and grades live in `operator_briefing` or on the page.
3. No `logs/_tmp_*.py`, no one-off extract scripts, no `SELECT *` on `all_fields_rows` / `raw_scan_rows`. The third
   time a query is needed it moves into `generic_utils`.
4. Every stock id in every output is `EXCHANGE:TICKER`.
5. Street, pack and model prices stay separate; `left` is quoted as `"left"`; `pe_fwd` is never filled with EV / revenue.
6. One Daily budget. No suite publishes a second one. MTP is climate; backtest IC is support, not a gate.
7. Outside news comes after the deterministic orders, tagged OUTSIDE; it changes timing or grade, never a sort or a size.
8. Capital recycle is `capital-plan`, mesh letters are `mesh`, priors are `priors`: never a hand sum or hand-written JSON.

## 9. How a tool is built here

A new deterministic procedure has six parts. A review checks all six.

| Part | Where | Convention |
|---|---|---|
| Module | `src/generic_utils/<name>.py` | `from __future__ import annotations`, type hints, a docstring that says what it does not do, `load_recipe`, `build_<name>(pack_dir, *, recipe, ids, store)` returning tables and a `spec`, `write_<name>(payload, out_dir)` through `run_export.write_run_export`, a no-argument `<name>_local_main` |
| Recipe | `config/generic_utils/<name>.json` | Every knob (floors, windows, quantiles, lists) lives here, with a `_note` |
| CLI | `tv_scan_cli.py`: `_cmd_<name>` and a subparser | `--pack`, `--ids`, `--out-dir`, `--line` (one line per row) or `--quiet` |
| Refresh | `config/generic_utils/daily_refresh.json` `suites` | `after` names the suites whose folders it reads; `optional: true` unless the Daily cannot run without it |
| Tests | `src/tests/test_<name>.py` | unittest classes, imports inside the test methods, pure functions tested on small fixtures |
| Words | `CLAUDE.md` (one bullet), a skill or a skill section, `run_catalog.txt`, the Ledger entries for every new column and coded value, optionally a page template | The Ledger is the only glossary |
