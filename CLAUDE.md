# edgarDataManagementPython — Claude Code guide

Personal active-management research platform: TradingView scans → move-prediction / edge / MTP / projection DuckDBs → a compiled **briefing pack** → operator judgment (Book actions, Build-50, movers, risk). The operator (repo owner) runs a real book. Deterministic tools do the data work; the agent does judgment on top. README.md has the architecture.

## Environment

- Windows. Python 3.11 at the system path (no venv in use). `PYTHONPATH=src;.` is set by `.claude/settings.json`, so commands run from the repo root without a prefix. Skill text still shows `$env:PYTHONPATH='src;.'` for Cursor; it is harmless.
- Tests: `python -m pytest src/tests -q` (unittest-style classes, imports inside test methods). Run the relevant test file after any generic_utils / operator_briefing change.
- Outputs live under `logs/` (gitignored): `logs/tradingview_analysis/...` run folders and `logs/canvases/` operator pages.
- `.vscode/settings.json` holds DB connection settings. Do not read it or copy it anywhere.

## Output modes (the paste's Output line)

- `duckdb output` (default): stop at the suite folder. Before any SQL, Grep its `queries.txt` for the table or field (the pack one is ~130 KB; never read it whole).
- `canvas output`: also write the operator page: spec in the run folder (or `logs/canvases/YYYYMMDD/` outside a run) as `<name>-YYYYMMDD.json` → `python src/generic_utils/tv_scan_cli.py page --spec ...` → HTML beside it + `logs/canvases/index.html`. Tables point at the suite CSV/DuckDB as `source`; never retype rows. Fix every Ledger warning. Chat = short snapshot + link to the HTML.
- `data lists`: put name tables on that page. Wisdom always gets a page (`wisdom-YYYYMMDD`) with the Ledger.
- Never announce a page and stop. If rendering fails, finish in the suite's `.md` fallback.

## Refresh and update

- **Daily outputs (one fire, three pages).** The refresh runs every suite (data in the pack), but renders three pages by default (`daily_refresh.json` `templates`): **brief** (`brief-YYYYMMDD`, the quick scan: Highlights with industries and model state, Moves, Book update with cash, Earnings this week with the bar each print faces, Projections from the model / forward value / factor month) **board** (`board-YYYYMMDD`, the deep page: Plan, Catalyst book, Timing, Earnings bar, Safe park, Value, All names, Book) and **movers** (`movers-YYYYMMDD`, the tape: day / week / 5D / 1M Top 25 up and punished BOUNCE vs CONTINUE_DOWN, Plan tab from `pages.movers.blocks` plan_0..plan_3, Course / Reason from `courses`). Each read lives in one place: the brief never repeats the board's plan or the movers tape, and the 13 older pages (daily_focus, playbook, gmv, wisdom, earnings_week, alpha_model, signal_lab, week_plays, outlook, print_brief, deterioration, pathway, peer_value) are deep dives rendered on demand: `page-all --set all`, or `--templates outlook,print_brief` on a print night, `deterioration,pathway` in a drawdown, `alpha_model,signal_lab` on a model review. The full Daily (`daily_full.txt`) still fills and renders every page (`--set all`); baseline and UPDATE fill brief + board + movers.
- **Decision journal:** `python src/run_journal.py` (record the newest pack + day judgment, review, render `journal-YYYYMMDD`; `--backfill` first time, `--history IDS`, `--note IDS --text ...`). One small DuckDB (`logs/tradingview_analysis/journal/journal.duckdb`, recipe `config/generic_utils/journal.json`): per session the regime, a snapshot of every covered name (pack reads, one row per name per day), the judgment's calls only when they change (reason text once) and dated notes (OUTSIDE news, sentiment, lessons: `tv_scan_cli.py journal note`); `journal review` measures calls and covered names on the panel store at 1 / 7 / 28 / 56 / 91 / 182 days (excess vs the median store name, signed by the call) into PACK/journal. The refresh suite `journal` and `priors` record automatically. Before re-ruling a name, read its `journal history`. The panel store carries `fwd_91d` / `fwd_182d` labels (3 / 6 months) for every reader.
- **One command:** `python src/run_operator_day.py` (manual brief + data-only pages) or `python src/run_operator_day.py --agent` (refresh, then a headless Claude run: full Daily if today has no judgment file, else UPDATE; `--print-prompt` to paste instead; UPDATE skips the agent when nothing moved). Prompts: `src/research_prompt/agent_runs/`.

- Earnings week on its own: `python src/generic_utils/tv_scan_cli.py earnings-week --pack PACK --ids A,B --line` (PACK/earnings_week; the refresh runs it as an optional suite).
- Week plays: `tv_scan_cli.py week-plays --pack PACK --ids A,B --line` (PACK/week_plays: `plays`, `book`, `cells`) joins the earnings-week calendar, alpha bands / deciles, entry book + safety band, balance sheet and the signal-lab print cell each name sits in now; the refresh runs it after signal_lab and `page-all` renders `week_plays` (its `month` / `month_ind` tables are the alpha model's month-ahead read per name and industry). Yesterday's calls: `tv_scan_cli.py play-review --pack PACK --line` (PACK/play_review: the newest prior judgment's courses and published bands against this pack, `ret_fx`, band / kill state on opens and closes).
- Catalyst outlook: `tv_scan_cli.py outlook --pack PACK --ids A,B --line` (PACK/outlook: `names` in the recipe's `column_groups` order technical / setup / surprise / value / progression / lists, `events`, `days`) puts every US $2B+ name's catalysts over six weeks (day-file earnings + slot, ex-dividend, IPO lockups, dated OUTSIDE rows in `config/generic_utils/catalyst_calendar.json`) beside the day's suites; the refresh runs it after week_plays and `page-all` renders `outlook`. Page tables take `column_groups` (a header row per group; `column_groups_from` reads a recipe) and long text cells clamp to two lines. Screens overlap: a click adds a screen and the grid keeps rows that pass every active one (Low bar + Tonight, Low bar + Model 7+); a screen in the same `group` (or, ungrouped, on the same column) replaces the clashing one, Ctrl+click overlaps anyway, Shift+click isolates, each button shows the rows a click would leave, typed filters stay; templates write atomic screens (When / Bar / Setup / Family groups, ungrouped strength facets) rather than compound presets. Every grid sorts (click, shift-click for a second key), moves columns by dragging a header (remembered per page and table), and has a toolbar: row search, per-column filters (`>5`, `1..10`, `=x`, `!x`, `a|b`), a columns menu, Heat, Stats (median footer), CSV of the visible grid, Reset; header tooltips are the Ledger meanings (renderer only, `canvas_page.py`).
- Print night: `tv_scan_cli.py print-night --pack PACK --line` (PACK/print_night: `names`, `matrix`, `pointers`, `cells`, `base`, `history`) takes every name whose reaction lands on the next session (`--react-on today` the morning after, `--sessions N`) and puts it on measured pointers: each pre-print field (tape, history, estimates, street, value, model, peers this season; after the print the surprise, mix, after-hours read, reaction) cut into quintiles on the lab's past prints, the cell's lift vs every other print on the reaction / 7d / 28d hold (after: after-hours-to-close, drift), with an arrow only where t, n, both halves and the hit rate agree (`config/generic_utils/print_night.json`); per name the counts up / down, the families, the lists, the overnight tail in starter dollars. The refresh runs it after week_plays; the outlook page shows its tabs (Tonight, Tonight pointers, Tonight digest, Pointer evidence) only when it exists, with one-click screens and a Guide tab (renderer `screens` / `guide`, tab `requires`). `tv_scan_cli.py print-brief --pack PACK` (PACK/print_brief: `cards`, `industries`) writes one short read per reporter from the pack's numbers (into the print, value to peers and its own history, what the quarter has to show, the industry's prints this season, pointers, levels, what to read on the print); the refresh runs it after print_night and `page-all` renders `print_brief` (renderer `cards` block; the judgment adds `pages.print_brief.notes`, OUTSIDE lines per name).
- Deterioration: `tv_scan_cli.py deterioration --pack PACK --ids A,B --line` (PACK/deterioration: `cells`, `names`, `letters`) puts every drawdown from the 52-week high on the panel store with the letters beyond price (E EPS estimate cut, R revenue estimate cut, C negative FCF, S last miss; rules in `config/generic_utils/deterioration.json`) and measures what each state did next (mean / hit / q10 excess, odds of a further -10% and of regaining half the gap, by market regime and 12-month run); live rows add the Book's cell dollars and recovery levels. The refresh runs it after week_plays and `page-all` renders `deterioration`. Rules: `documentation/market_insights/deterioration_playbook.md`. Recovery ladder: `tv_scan_cli.py recovery --pack PACK --line` (PACK/recovery_ladder: `lines`, `ladder`) gives each Book line's road back to cost and to +10%, and what an add at the close / bounce band does to its average, its break-even against the 50-day and its loss at the kill (refresh suite after deterioration). Recovery clock: `tv_scan_cli.py recovery-clock --pack PACK --line` (PACK/recovery_clock: `lines`, `reach`, `cells`, `curves`; `config/generic_utils/recovery_clock.json`) starts every $2B+ name weekly in its deterioration state and measures, with Kaplan-Meier censoring, how often and how fast the close touched each rise / half-way / the high, the path low first (`floor_<W>`) and the 91-day end vs the median name (`fx_<W>`); each Book line gets the odds and median days to its cost, 50-day and half-way, and its cell's floor in price and dollars (on demand).
- Event risk: `tv_scan_cli.py event-risk --pack PACK --ids A,B --line` (PACK/event_risk: `book`, `names`, `sell_book`, `buy_book`, `events`, `reactions`, `crashes`, `follow`, `evidence`; `highlights.log`; recipe `config/generic_utils/event_risk.json`) gives every US $2B+ name, Book line and named id a crowd (its 15 most-correlated names on the store, corr >= 0.35), the crowd's move / drawdown / z, a stress (the worse of the crowd's worst 5-step move x down-beta and the line's own worst 5-step move; dollars and % NAV on held lines), the calendar events that touch it (`symbols`, an `exposure` map `{down|up|either: [themes]}` by membership or 40% of the crowd's cap, a market-wide binary `policy` row = P on every unmapped line, `odds_kind` from `sentiment_outside.json`), letters `EPRUSBTVD$` and `warn_level` WARN_STRONG / WARN / WATCH from fixed rules (a review trigger, never a size or a second budget). Only policy / binary / mapped events are credited with a crowd's move (R / U). **Core warning field:** the refresh runs it right after movers and book_risk (D letters come from the store), so deterioration, earnings_week, outlook, pathway and board join `warn_level` / `er_letters` / `stress_5s_usd` / `ev_next` / `ev_recent_z` (recipe `joins`); `stance` / `lookup --line` end a flagged name with `warn=WARN_STRONG RBTV$ $-1616 (-1.13% NAV) evz -4.09` (no level, no bytes; `event_risk.warn_token` / `warn_lookup`); the brief's Book tab and the board's Event WARN / Event lifted screens show it and UPDATE flags a held line's level change (`warn A->B`). Token economy: read `highlights.log` (~5 KB: levelled Book lines in full, the rest on one line, the first 8 of each list), never `names.csv` (~780 KB); sell / buy lists keep slim columns (`sell_buy.fields`). Every WARN_STRONG Book line needs a Reason that says what it does about the event. `--as-of D` replays the store point-in-time (run on 2 Nov 2026 it put NASDAQ:STRL at WARN_STRONG before the sweep, in-sample).
- Deep-dive agent: `python src/run_deep_dive.py --ids A,B [--theme T] [--question Q] [--agent | --print-prompt]` (or `deep_dive_analysis_agent(...)` in `src/main.py`) writes `logs/tradingview_analysis/name_dossier/<stamp>_<label>/`: `tv_scan_cli.py dossier` (generic_utils.name_dossier, recipe `config/generic_utils/name_dossier.json`) gathers per name the board row and every suite join, the store's daily progression and movement anatomy, prints, analog forward paths (nearest US $2B+ name-days on day-ranked features; raw, excess, all floor vs same industry, `n_dates`), evidence directions per horizon (counts), live band / kill (`band_live_*` / `kill_live`: the bounce band when the entry book sits above the close), peers, dated events and a research plan into `dossier.md`; the agent adds the outside read and writes `dossier.judgment.json` (verdict, band, kill, targets, SHORT / MID / LONG trajectory classed DATA_BACKED / MIXED / NARRATIVE, suite order, `question_read`), rendered by `tv_scan_cli.py dossier-page --dir DIR --strict`. Not the watchlist `deep-dive` page (generic_utils.deep_dive); verdicts are candidates for the Daily's one budget.
- Market sentiment: `tv_scan_cli.py sentiment --pack PACK --line` (PACK/sentiment: `daily`, `readings`, `cells`, `families`, `patterns`, `outside`; `highlights.log`; recipe `config/generic_utils/market_sentiment.json`) builds one row per store file on the US $2B+ floor (cap-weighted move and index, breadth, up-volume share, volume pace scaled for the session seen at scan time, distribution / accumulation days, RSI stretch, dispersion, beta / momentum / defensive / AI-cluster spreads, beat and miss reactions, revision breadth, move-prediction score medians, the MTP ENTER share) and measures each reading against the cap index's next 1 / 5 / 10 / 21 sessions (rank IC, t on n_indep = days / h, halves, today's quintile lift; `read_<h>` ▲ / ▼ only when all agree), plus named volume / breadth patterns (`patterns`: SQL conditions on `daily`, live today, episodes, lift after). Families count arrows, never a sum (no 0-100). OUTSIDE readings (fear / greed, AAII, VIX, prediction markets) go in with `tv_scan_cli.py sentiment-add --kind K --value V --date D --source S --link L`; shown, never measured into an arrow. `run_market_timing_policy.py` writes the same read into its run folder (`market_sentiment/`, manifest `market_sentiment`; `--sentiment-only`, `--no-sentiment`). The refresh runs it as the optional suite `sentiment`; the brief shows it on its Sentiment tab. With months of store, most readings carry no arrow yet: read the percentile, the quintile lift and the live patterns as context, not a forecast.
- Downside: `tv_scan_cli.py downside --pack PACK --line` (PACK/downside: `steps`, `windows`, `dist`, `episodes`, `replay`, `lines`, `scenarios`, `plans`) measures each Book line's beta to the store's cap-weighted US floor (all, down sessions), replays today's Book through the store's own drawdowns (market, median name, AI cluster), gives the Book's dollars for each market move and what each capital plan does to beta (`spec.plans_after`); refresh suite after deterioration. Page tables can sit beside a `chart` block (inline SVG lines from a source, `canvas_page.py`).
- Forward value: `python src/run_financial_projection.py` (growth lanes, then the `finvalue_*` run; `--mode value` in `main()`) values every all-fields name over at most 5 years: year 1 = the street's revenue / EPS forecasts, decaying growth and margins toward the industry, a year-5 exit P/E (EV/Sales for loss makers), discounted at a beta-based cost of equity (`financial_projection/valuation.py`, `config/financial_projection/value_v1.json`). The pack joins it: `pe_fwd` / `fp_pe_y1` / `fp_pe_y5` from the street-anchored path and `fv_*` (fair value bear / base / bull and weighted, `irr_exp_pct` vs `hurdle_pct`, `priced_in_cagr_pct`). Guide: `documentation/financial_projection_usage.md` section V. Cycle scenarios: `tv_scan_cli.py cycle --pack PACK --ids A,B --line` (PACK/cycle_scenarios: `names`, `grid`, `stress`; `--shocks CSV`) reads what each price already assumes about a boom ending: k more boom years after the street's year 1, then an EPS drop d, valued on owner cash and a through-cycle exit P/E; `drop_in_k<k>` = the bust the price pays for, `pe_need_k<k>_d<d>` = the exit multiple it needs (`config/generic_utils/cycle_scenarios.json`).
- Peer value: `tv_scan_cli.py peer-value --pack PACK --ids A,B --line` (PACK/peer_value: `names`, `groups`, `peers`, `evidence`, `quantiles`; `config/generic_utils/peer_value.json`) puts every US $2B+ name's multiple (forward P/E, EV/EBITDA, EV/sales) against its TradingView industry (the sector when thin): `prem_pct` to the peer median, `just_pct` = the premium its growth and quality earn in the industry's ridge fit, `gap_pct` = fitted vs actual (positive = cheaper than peers with the same profile), `px_fit`, percentiles and spreads to peers, PEG and the forward-value run's priced-in growth / IRR vs the group, the five nearest peers by market cap, what each industry pays per driver (`pay_*`), and whether the gap paid on the store's forward returns. A growth or quality premium can be priced in on its own and still be cheap or rich against peers: read `gap_pct` beside `prem_pct`. The refresh runs it after movers (before earnings_week); deterioration, pathway and earnings_week join `peer_gap_pct` / `peer_prem_pct` / `peer_just_pct` / `peer_px_fit`; `page-all` renders `peer_value` and wisdom shows the Book and focus rows.
- Opportunity board: `tv_scan_cli.py board --pack PACK --ids A,B --line` (PACK/board: `names`, `groups`; `config/generic_utils/opportunity_board.json`) joins every outlook name with peer value, deterioration letters and cells, the beat bar (W0 / W1 reporters: `bar_runup` / `bar_tape` / `bar_rev` terciles, T1 = low bar), forward value, anatomy letters and store beta / `rvol_20`, plus the close against the bounce band (`band_state`, `to_band_high_pct`, `kill_dist_pct`). The refresh runs it last; `page-all` renders `board` (`board-YYYYMMDD`): a Plan tab from the judgment (`pages.board`: `ids`, `blocks.stats`, `read`, `plan` / `earnings` / `park` / `book` as `{rows, tones}`, `timing`, `change`, `sources`) and grids with screens (Timing, Earnings bar low / high bar, Safe park, Value, All names, Book). It is the day's summary page: fill it on every Daily and UPDATE. Its **Catalyst book** tab (`pages.board.catalyst_ids`, `blocks.catalyst_read` / `policy` / `catalyst`, cash preview from the judgment's `capital_plan.capital_plan_catalyst`) keeps names where an outside catalyst (policy, a dated print, a vote) could move the price and the data agrees, in three lanes: policy / sentiment, discounted names turning up (the Value screen 'Discounted, strong, turning up'), AI upside with a dated catalyst. It shares the Daily's one budget: NEW (queue) / WATCH with band and kill, and a stated order for the next NEW slots. Theme lists: `policy_midterm_up`, `policy_midterm_down`, `discount_turn`, `ai_upside_catalyst` in `themes.json`.
- Focus book (on demand): `page --template focus_book` (`focus-book-YYYYMMDD`, in `templates_all`) is the highest-margin book for the next two weeks and the month: the judgment's `pages.focus_book` (`ids`, `blocks.stats` / `read` / `market`, `focus` and `book` tables with band, kill on a close, target, up %, risk %, up / risk, `stages`, `events`, the MU / memory, AI-lane, shorts and Outside tabs, `rules`, `sources`) beside lane tables read from `PACK/analysis_scans/<lane>.csv` (`focus_book`, `two_week_events`, `unpriced_revisions`, `quiet_accumulation`, `shorts_focus`, `ai_lane`: `tv_scan_cli.py focus` on `PACK/board/board.duckdb`, recorded in the judgment `scans` so UPDATE replays them), the cycle-scenario and recovery-clock rows, and cash from the three capital plans. `entry_px` / `month_up_pct` / `risk_pct` / `payoff` / `ai_cluster` are standing Ledger keys; `payoff` orders one lane and is never summed with another read.
- Lane book: `tv_scan_cli.py lane-book --pack PACK --ids A,B --line` (PACK/lane_book: `lanes`, `lane_months`, `names`, `when_value`, `when_spread`, `rotation`, `industries`, `timeline`, `weeks`, `capital`; `highlights.log`; recipe `config/generic_utils/lane_book.json`) makes each lane one SQL condition on the panel store (`defs` macros, the cluster flag `ai`, `<field>_pr` day ranks) and gives it a record (raw / excess at 7 / 14 / 28 days, odds of +10% / -10%, block t, halves, months, AI cluster vs the rest) and its names today with the board's band / kill / targets; `when_*` is value quintile x catalyst timing (when a discount pays), `rotation` the industry quadrants' record, `timeline` / `weeks` the outlook events plus calendar rows the pack has not seen, `capital` the cash above the floor. The refresh runs it after board; `page --template lane_book` (`lane-book-YYYYMMDD`, in `templates_all`) renders data-only or with `pages.lane_book` (road, tickets, stages, Book, Outside, Critical) and the `capital_plan_lane` scenario. Skill `.claude/skills/lane-book`. In-sample, one regime: read the base row, t, halves and months before a mean. What moves against what: `tv_scan_cli.py rotation-pairs --pack PACK --line` (PACK/rotation_pairs: `baskets`, `pairs`, `ind_pairs`, `series`; recipe `config/generic_utils/rotation_pairs.json`; optional refresh suite) turns baskets (AI cluster, chips, memory, software, staples, insurance, health ...) into cap-weighted store lines and gives each pair its correlation with the market's step out (`corr_resid` < 0 = they move against each other), A over B per window, today's percentile and what followed past extremes (`hi_*` / `lo_*` with `nind`); the lane book page shows it on its Pairs tab.
- Pathway: `tv_scan_cli.py pathway --pack PACK --ids A,B --line` (PACK/pathway: `exposure`, `lines`, `attribution`, `regime`, `factor_tape`, `candidates`) sets the Book's NAV-weighted factor percentiles beside each factor's signal-lab IC (record, this month, the trailing tape), splits the Book's 1M / 3M gap into industry and stock parts, and gives each trim's / starter's effect on the tilt; the refresh runs it after deterioration and `page-all` renders `pathway` (stages and triggers are judgment, staged cash via `capital_plan_pathway`). Rules: `documentation/market_insights/investing_pathway.md`.

## Invariants (do not renegotiate)

- **No invented 0–100 composites.** `rr`, `bo`, `band_payoff`, Support, ras, IC are separate columns and separate orders. Never add `rr` and `bo`. The alpha model's `pred_<h>` is a fitted forecast in percent with an out-of-sample record and a `state`: its own order, never summed with `rr` / `bo` / `left`, never a gate or a size.
- **No `logs/_tmp_*.py`, no one-off extract scripts, no `SELECT *` on `all_fields_rows` (~3.5k cols) or `raw_scan_rows`.** Use the CLIs (`tv_scan_cli.py`, `rank_cli.py`, `example_entry.py`, `run_operator_suites.py`). Third time the same SQL is needed → promote it into `generic_utils` first.
- **Generic vs domain:** formulas, fetch, aggregate, top-N with zero cutoffs live in `generic_utils`. Eligibility, ADD/WAIT/PASS, polar continuity, High/Med/Low stay in `operator_briefing` or on the page. Never put thresholds in `ranking.py`.
- Leftover `left` = max(street PT upside, edge forward upside). Quote the DuckDB column as `"left"` (reserved word). Street, pack, and model (`fp_*`) prices stay separate. `edge_only` does not get a NEW.
- Quote `val_field` (the setup's native multiple), not EV/Rev for every name. Never fill `pe_fwd` with EV/Rev. A bin label (ABOVE/DISCOUNT/PAID…) always sits beside its percent.
- **Polar rule:** yesterday's ADD/NEW cannot become EXIT unless `thesis_kill`. `avoid_value_trap` on a live-leftover Book line → HOLD_NO_ADD. DERISK sticks while dte ≤ 7; TRIM sticks until tape repairs.
- MTP ENTER_SMALL/ENTER_PROBE is climate, not a buy list. Backtest IC is support, never a leftover gate. Catalyst PASS-all is not a filter.
- Capital recycle (EXIT/TRIM cash into starters, industry NAV % after) is `tv_scan_cli.py capital-plan`, never a hand sum. Mesh letters are `tv_scan_cli.py mesh`; mover leader classes are `up_class` from `sleeves.classify_up_tape`.
- Budget per Daily: 0–2 NEW, 0–2 ADD, 0–2 TRIM/EXIT, 0–2 event, 0–1 short. One budget only; other suites never publish a second NEW/ADD budget. Starter ≈ $5,000, add to a held line ≈ $1,000 (advice, not a cutoff).
- **Stock ids are always `EXCHANGE:TICKER`** (`NASDAQ:MU`, `XETR:VUAA`, `OMXCOP:NOVO_B`) in every output: scan tables, CSV / DuckDB, md, page tables and text, judgment `courses`, priors keys, capital plans, and chat. A bare `ticker` column may sit beside `symbol`; it is never the only id. Bare tickers are an input convenience only (CLIs resolve them). Code: `generic_utils.symbol_identity` (`qualify`, `display_id`, `qualify_rows`); an id that is missing or listed on two exchanges stays bare and is reported, never guessed.
- **Ids that go missing or old (one resolver, every area):** TradingView's primary listing moves (Alphabet flipped NASDAQ:GOOG → GOOGL on 2 Nov 2026) and tickers get renamed (NYSE:SQ → NYSE:XYZ). Scans keep US secondary share classes / ADRs (`with_us_secondary_listings`: all-fields and move-prediction). Any code that cannot find a held or named id in its own run resolves it with `generic_utils.symbol_resolver` in this order:
  1. `config/generic_utils/symbol_aliases.json` (old id → current; written by hand).
  2. The caller's own run.
  3. The newest all-fields day DuckDB, newest run.
  4. The panel store's last row (with `age_days`).
  5. Otherwise it is reported. The holdings scorer marks such lines (`close_source = symbol_resolver.*`, `match_note = not_in_source_run`) so the Book and NAV keep them, and compile adds `book_missing` plus a pack note for any config line still off the Book.

  Never substitute a sibling class (GOOG is not GOOGL) or another exchange. `tv_scan_cli.py symbol-check [--ids ...] [--flagged]` lists ids that look old with candidates (same company under another id, same ticker on another US exchange); a confirmed one goes into the alias file. Run it when a pack note says a held line is missing.
- DAILY compare uses `compare --session --exchanges NASDAQ,NYSE,AMEX`. `history`/`span` take full `EXCHANGE:TICKER` ids.
- Outside news only after the deterministic orders exist, tagged `OUTSIDE`; it can change timing or Grade, never a sort key or size.
- After publishing a Daily, write priors with `python src/generic_utils/tv_scan_cli.py priors --day YYYYMMDD --notes "..."` (from the judgment, keys `EXCHANGE:TICKER`, merges on UPDATE). Do not hand-write the priors JSON.
- Do not rerun multi-hour producers (`run_backtests.py`, scan producers) unless asked; prefer `run_operator_suites.py sources` / existing folders.

## Code conventions

- Match the surrounding module: `from __future__ import annotations`, type hints, short module docstring stating what it does *not* do (no cutoffs, no 0–100), recipes/knobs in `config/generic_utils/*.json`, no-arg defaults in a `*_local_main` function.
- Do **not** add `=== AI GENERATED CODE ===` markers; `AI_CODE_DOCUMENTATION_RULES.md` is retired for Claude work.
- New CLI procedures go in `tv_scan_cli.py` as `_cmd_<name>` + subparser, writing a run folder with DuckDB + `overview.log` + `queries.txt` via `run_export`.
- Git: ask before commit, push, reset, clean, rebase. Read-only git and `git mv` are fine.
- **Patch notes (`documentation/patch_notes/`, skill `patch-notes`).** Before building: Grep `capability_index.md` (generated: every runner, CLI subcommand with its help, module with purpose / recipe / test, refresh step, skill) for the verb or noun, then `feature_register.md` (generated: per feature its status, entry points, the commit it arrived in, the last change and the patch numbers that changed it; first-seen and removed lists) and the numbered patch files it names; never read a generated file whole, and do not build on a feature whose status is `deprecated`. Before a commit of more than a few files: `python src/generic_utils/patch_scan.py scan` (staged; `--worktree`, `--commit SHA`, `--range A..B`) writes `logs/patch_notes/<stamp>/inventory.md` (areas, features touched, anything removed with the files that still refer to it, deprecation wording in added lines, functions added / changed, CLI and recipe changes, wiring of new modules, lint, guards); review the code it points at, measure (refresh timings in `refresh.json`, a before / after on real data), run the tests, then write `NNNN_YYYYMMDD_<slug>.md` from the skeleton (what the operator can do now, a Feature changes table with added / updated / renamed / on_demand / deprecated / removal_requested / removed, technical changes, numbered findings with status, follow-ups) and run `patch_scan.py regen`. A review fix stays unstaged until the user takes it. **Deprecating or removing a feature happens only on the user's request or when the change set does it**: record it in `documentation/patch_notes/lifecycle.json` in that patch, remove all six parts of the tool together, and commit no `removed but still referenced` finding without a sentence that explains it; a candidate the user has not decided on goes into the patch's Follow-ups. `0000_baseline_*.md` is the starting point; its section 10 and each patch's Follow-ups list the known debt.
