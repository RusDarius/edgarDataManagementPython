# AI Code Documentation Rules

## Overview

This document establishes universal rules for documenting AI-generated code in this project to maintain clear provenance and transparency. These rules apply to **ALL AI models** including Claude, GPT, Gemini, Copilot, and any other AI systems used in development.

## Core Rules

### Rule 1: AI Code Marking

All code generated by ANY AI model must be marked with a comment at the beginning of the generated section:

```python
# === AI GENERATED CODE START ([MODEL_NAME]) ===
# Generated on: [DATE]
# Model: [AI_MODEL] (e.g., Claude-3.5, GPT-4, Gemini-Pro, GitHub Copilot)
# Purpose: [Brief description of what this code does]

[AI generated code here]

# === AI GENERATED CODE END ===
```

### Rule 2: Modification Marking

When AI modifies existing human-written code, mark the modified sections:

```python
# === AI MODIFIED CODE START ([MODEL_NAME]) ===
# Modified on: [DATE]
# Model: [AI_MODEL]
# Changes: [Brief description of changes]

[modified code here]

# === AI MODIFIED CODE END ===
```

### Rule 3: Function-Level Documentation

For entire functions generated by AI, add a comment at the function definition:

```python
# === AI GENERATED FUNCTION ([MODEL_NAME]) - [DATE] ===
def my_ai_generated_function():
    """
    AI Generated Function: [Purpose]
    Generated by [AI_MODEL] on [DATE]
    """
    # function body...
```

### Rule 4: Collaborative Code

For code that was developed collaboratively (human + AI), mark sections:

```python
# === COLLABORATIVE CODE (Human + [MODEL_NAME]) ===
# Human: Original structure and logic
# AI Model: [AI_MODEL] - Enhanced error handling and output formatting
# Date: [DATE]

[collaborative code here]

# === COLLABORATIVE CODE END ===
```

## Implementation Guidelines

### When to Apply Rules

- **Always**: When AI generates new functions, classes, or significant code blocks
- **Always**: When AI modifies existing human code
- **Sometimes**: For minor AI suggestions or single-line changes (use discretion)

### Comment Format Standards

- Use `===` for clear visual separation
- Include the AI model name in brackets (e.g., Claude, GPT-4, Copilot)
- Include the date in YYYY-MM-DD format
- Keep purpose descriptions brief but clear
- Use consistent indentation with the surrounding code

### AI Model Identification

Use these standard identifiers:

- **Claude**: Claude-3.5, Claude-3, etc.
- **OpenAI**: GPT-4, GPT-3.5, ChatGPT, etc.
- **Google**: Gemini-Pro, Bard, PaLM, etc.
- **GitHub**: Copilot, Copilot-Chat, etc.
- **Microsoft**: Copilot, Bing-Chat, etc.
- **Anthropic**: Claude variants
- **Other**: Use official model name

### Documentation Locations

1. **Function Level**: At the function definition
2. **Block Level**: At the start of significant code blocks
3. **Inline**: For specific modified lines when appropriate

## Maintenance

- Review and update these rules as needed
- Ensure all team members and AI tools follow these conventions
- Periodically audit code for proper AI attribution
- Update documentation when rules change
- Train new AI models/tools on these standards

## Benefits

1. **Transparency**: Clear understanding of code origins across all AI tools
2. **Maintainability**: Easier to understand code evolution regardless of AI source
3. **Debugging**: Faster identification of potential AI-related issues by model
4. **Learning**: Helps humans understand different AI contributions and patterns
5. **Legal/Compliance**: Clear documentation for intellectual property purposes
6. **Tool Comparison**: Ability to compare effectiveness of different AI models
7. **Accountability**: Clear attribution for AI-generated code quality
